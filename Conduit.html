Conduit

Conduit — job queue and durable workflow engine for March.

This module is the top-level namespace. It re-exports the types shared across all subsystems (errors, config, job metadata, workflow types, etc.) and provides thin forwarding wrappers so callers can write Conduit.pause_cron(...) instead of the fully-qualified Conduit.API.pause_cron(...).

Typical startup sequence:

  1. Register performers: Conduit.API.register(job_type, performer, config)
  2. Register crons: Conduit.API.register_cron(cron_type, cron_config, performer)
  3. Register workflows: Conduit.API.register_workflow(wf_type, runner, wf_config)
  4. Start the engine: Conduit.API.start(config, storage)

All types below are intentionally kept in this file so that library consumers have a single import point for the entire Conduit type vocabulary.

Types

typeConduitErrorConduitError = Retry(String) | Discard(String) | Snooze(Int) | WorkerError(String)#

ConduitError is returned by performer functions to control what the worker does after a job finishes unsuccessfully.

Retry(msg)       — transient failure; reschedule using the job's backoff
                   strategy.  `msg` is appended to the job's error list.
Discard(msg)     — permanent failure; do not retry.  Routes to the
                   dead-letter queue if one is configured, otherwise marks
                   the job dead in-place.
Snooze(ms)       — postpone: reschedule the job to run after `ms`
                   milliseconds without consuming a retry attempt.  Used
                   internally by the rate-limiter and available to
                   performers that need to wait for an external resource.
WorkerError(msg) — unexpected infrastructure error (caught exception,
                   storage failure).  Treated the same as Retry; the
                   distinction lets callers identify system vs. domain
                   failures in logs.
typeSchemaSchema(a) = { validator : Option(a -> Result((), String)) }#

Optional argument validator attached to a job or cron. When validator is Some(f), Conduit.Schema.validate calls f on the decoded arguments and propagates any Err back to the caller before the job is enqueued. Use Conduit.Schema.none() to skip validation.

typeBackoffBackoff =#

Controls the delay between retry attempts. The worker calls Conduit.Backoff.delay(strategy, attempt) and adds a random jitter (0–1 s) before scheduling the next attempt.

Linear         — delay = 5 s × attempt  (5 s, 10 s, 15 s, …)
Exponential    — delay = 2^(attempt-1) s  (1 s, 2 s, 4 s, 8 s, …)
Fibonacci      — delay = fib(attempt) s   (1 s, 1 s, 2 s, 3 s, 5 s, …)
Custom(f)      — delay = f(attempt) ms, fully user-controlled.
                 `f` receives the 1-based attempt number and must return
                 a non-negative integer of milliseconds.

Internal constructor names are unique (prefixed with Conduit) so they do not clash with the stdlib Backoff / QuantileMethod types that were added in newer march releases. The public API is exposed via let constants and a fn Custom helper in lib/conduit/backoff.march.

typeUniqueScopeUniqueScope = PerQueue | Global#

UniqueScope controls the boundary of uniqueness:

PerQueue  (default) — one active job per (queue, job_type, fingerprint).
                      The same job type can still be unique-per-queue in
                      different queues simultaneously.
Global              — one active job per (job_type, fingerprint) across
                      all queues.
typeUniqueConstraintUniqueConstraint = {#

UniqueConstraint is set via JobConfig.unique_for.

duration  — how long (ms) the unique lock is held after the job
            completes.  Set to 0 to release immediately on completion.
fields    — JSON field names to include in the fingerprint.  An empty
            list includes the entire raw payload string.
scope     — see UniqueScope above.
typeUniqueConflictUniqueConflict = Ignore | Replace | Raise#

UniqueConflict controls what happens when a unique constraint fires:

Ignore   (default) — silently return the id of the existing job as if
                     enqueue succeeded.  The new job is dropped.
Raise              — return `Err("unique constraint violated …")` to the
                     caller.  Nothing is inserted.
Replace            — cancel the existing job and insert the new one.
typePerKeyRateLimitPerKeyRateLimit = {#

PerKeyRateLimit adds a secondary per-entity bucket on top of the global per-job-type bucket.

key_fn  — extracts a discriminator from the job payload string.
          e.g. `fn payload -> Json.get_string(payload, "user_id")`
limit   — tokens/second for this entity bucket.
typeRateLimiterBackendRateLimiterBackend =#

RateLimiterBackend selects the token-bucket implementation:

StorageBacked       — Postgres token bucket via the storage interface.
                      Correct under multi-node deployments; recommended
                      default.
Custom(f)           — user-supplied function `f(key, rate) ->
                      Result(Bool, String)`.  Return `Ok(true)` to allow,
                      `Ok(false)` to deny (snooze), `Err(e)` on storage
                      failure (worker will proceed anyway to avoid
                      blocking the queue).  Use for Redis, in-process
                      sliding windows, or any other backend.
typeRateLimitRateLimit = {#

RateLimit is set via JobConfig.rate_limit.

max_per_second  — global token allowance across all instances of this job
                  type; 0 means unlimited.
per_key         — optional secondary per-entity bucket (see PerKeyRateLimit).
backend         — token-bucket implementation (see RateLimiterBackend).
typeJobConfigJobConfig = {#

JobConfig is set once per job type, typically via fn config() on the job module, and passed to Conduit.API.register. At runtime the worker reads it from the in-process registry to control retry, timeout, and routing.

queue             — name of the queue this job is enqueued into.
                    Defaults to "default".
max_attempts      — maximum number of executions before dead-lettering.
                    Attempt 1 is the first try; retries start at attempt 2.
                    Defaults to 3.
timeout           — milliseconds before the worker considers the job hung.
                    The heartbeat interval is derived as timeout / 3
                    (minimum 5 s).  Defaults to 30 000 (30 s).
backoff           — delay strategy between retries (see Backoff).
                    Defaults to Exponential.
dead_letter_queue — optional queue name for the DLQ.  When set, exhausted
                    and discarded jobs are written to conduit_dead_letters
                    and a `conduit_queue_<dlq>` NOTIFY is fired.  When
                    None the job is marked dead in-place without a DLQ row.
unique_for        — optional uniqueness constraint (see UniqueConstraint).
on_conflict       — behaviour when a unique constraint fires (see
                    UniqueConflict).  Defaults to Ignore.
rate_limit        — optional token-bucket rate limit (see RateLimit).
on_dead_letter    — optional callback fired synchronously after a job is
                    moved to the dead-letter table.  Receives a JobInfo
                    snapshot of the failed job.  Must not block or panic.
priority          — scheduling priority.  Higher values are polled first.
                    Defaults to 0.
tags              — arbitrary string labels stored on the job row and
                    queryable from the dashboard.
discard_after     — optional age limit in milliseconds.  Jobs older than
                    this are discarded without retry.  Not yet enforced by
                    the worker (Phase 6).
typeJobInfoJobInfo = {#

JobInfo is a read-only snapshot passed to the on_dead_letter callback and available to performers that have been injected their own metadata. It does not include all fields of JobRow; only the information useful to application-level dead-letter handlers.

id           — UUID of the job row.
queue        — queue it was enqueued in.
job_type     — string name of the performer module.
attempt      — the attempt number that just failed (1-based).
max_attempts — the configured maximum (same as JobConfig.max_attempts).
tags         — tags from the original JobConfig.
inserted_at  — when the job was first enqueued.
errors       — all error messages accumulated across all attempts.
typeRetentionConfigRetentionConfig = {#

RetentionConfig controls how long terminal rows are kept before the leader-only background pruner deletes them in batches. Set Config.retention = Some(RetentionConfig.default()) to enable pruning.

completed_after_ms  — delete completed jobs older than this.
                      Defaults to 86 400 000 (24 h).
dead_after_ms       — delete dead/discarded job rows AND their dead-letter
                      records older than this.  Defaults to 604 800 000 (7 d).
workflow_after_ms   — delete completed/failed/cancelled/timed-out workflows,
                      their checkpoints, signals, and events older than this.
                      Defaults to 604 800 000 (7 d).
prune_batch_size    — max rows per DELETE statement.  Keeps transactions short
                      and avoids long table locks.  Defaults to 1 000.
prune_interval_ms   — how often the pruner runs (on the leader).
                      Defaults to 300 000 (5 min).
typeConfigConfig = {#

Config is passed to Conduit.API.start and governs worker pool sizing, polling cadence, and cluster membership. See Conduit.Config.default() for production-ready starting values.

queues                  — list of queue names this node polls.  Each queue
                          gets `workers_per_queue` worker tasks.
workers_per_queue       — concurrent workers per queue.  Defaults to 5.
poll_interval_ms        — sleep between DB polls when the queue is empty.
                          Defaults to 1 000 ms.  Reduce for lower latency
                          at the cost of more DB traffic when idle.
cron_tick_interval_ms   — how often the cron scheduler checks for due
                          schedules.  Defaults to 30 000 ms.  Must be ≤ the
                          smallest cron interval you use (typically 60 s).
node_id                 — unique identifier for this process in the cluster.
                          Defaults to a random UUID; override with a stable
                          name for easier debugging.
heartbeat_interval_ms   — how often each node updates `last_seen_at` in the
                          cluster registry.  Defaults to 15 000 ms.
stale_node_threshold_ms — a node not seen within this window is considered
                          crashed; its in-flight jobs are reclaimed.
                          Defaults to 60 000 ms (must be > heartbeat_interval_ms).
drain_timeout_ms        — how long `Conduit.API.stop` waits for in-flight jobs
                          to finish before deregistering the node.  Workers
                          stop polling new jobs immediately when drain begins.
                          Defaults to 15 000 ms.
retention               — optional pruning config.  None disables the pruner
                          (default).  Set to Some(RetentionConfig.default())
                          to enable automatic table pruning on the leader.
typeCronOverlapCronOverlap = Skip | Allow | Replace#

CronOverlap controls what happens when a cron tick fires while the previous job is still running.

Skip    (default) — do not fire; wait for the next tick.
Allow             — fire regardless; multiple jobs may run concurrently.
Replace           — cancel the in-flight job and enqueue a fresh one.
typeCronConfigCronConfig = {#

CronConfig is passed to Conduit.API.register_cron. Fields:

schedule  — standard 5-field cron expression ("min hr dom mon dow").
            Examples: "0 * * * *" (hourly), "*/15 * * * *" (every 15 min).
timezone  — UTC offset string for schedule evaluation.  Defaults to "UTC".
            Supported forms: "UTC", "UTC+N", "UTC-N", "UTC+N:MM", "UTC-N:MM".
            Examples: "UTC+5:30" (India), "UTC-8" (US Pacific standard time).
queue     — queue to enqueue fired jobs into.  Defaults to "default".
overlap   — what to do when the previous firing is still running
            (see CronOverlap).  Defaults to Skip.
tags      — labels forwarded to the job row on each firing.
jitter_ms — optional random delay (0..jitter_ms ms) added to each fired
            job's run_at.  Prevents thundering-herd when many crons fire
            at the same second.  Defaults to None (no jitter).
typeCronScheduleCronSchedule = {#

CronSchedule is the DB row stored in conduit_cron_schedules. Static crons are upserted from their CronConfig each time Conduit.API.start runs; dynamic crons are managed via Conduit.API.schedule_cron.

id          — unique identifier; for static crons this is the `cron_type`
              string.  For dynamic crons use a UUID.
job_type    — the performer registered under this name handles execution.
schedule    — raw cron expression string.
timezone    — UTC offset string (see CronConfig.timezone).
queue       — queue for fired jobs.
payload     — JSON payload forwarded to the performer on each firing.
              Defaults to "{}".
overlap     — serialised CronOverlap ("skip" | "allow" | "replace").
enabled     — when false the scheduler skips this row entirely.
last_run_at — timestamp of the most recent successful firing.
last_job_id — job id produced by the most recent firing (used for Skip
              overlap check).
next_run_at — pre-computed next fire time (set after each firing).
tags        — forwarded to each fired job row.
jitter_ms   — optional per-firing random delay in ms (see CronConfig.jitter_ms).
typeJobRowJobRow = {#

JobRow mirrors the conduit_jobs DB schema. Workers fetch this struct from storage, execute the performer, and update the row through the storage interface. Application code typically does not construct JobRow directly; use Conduit.API.enqueue instead.

id                — UUID primary key, generated at enqueue time.
queue             — queue name.
job_type          — string key into the performer registry.
payload           — opaque JSON string forwarded verbatim to the performer.
status            — lifecycle state: "pending" | "running" | "completed" |
                    "failed" | "dead" | "snoozed".
attempt           — number of completed execution attempts (0 = not yet run).
max_attempts      — copy of JobConfig.max_attempts at enqueue time.
priority          — scheduling order; higher = polled first.
backoff           — serialised strategy name ("linear" | "exponential" |
                    "fibonacci" | "custom").  Custom functions cannot be
                    round-tripped; "custom" falls back to Exponential on
                    retry.
dead_letter_queue — copy of JobConfig.dead_letter_queue at enqueue time.
inserted_at       — when the job was first enqueued.
scheduled_at      — when enqueue was called (same as inserted_at for
                    immediate jobs; earlier for delayed jobs).
run_at            — earliest time the job may be picked up.  Workers skip
                    rows where run_at > NOW().
started_at        — set by mark_running when a worker claims the job.
completed_at      — set by mark_completed on success.
heartbeat_at      — updated every heartbeat_interval_ms while running.
                    Jobs with a stale heartbeat_at are candidates for
                    rescue_stale reclaim.
worker_id         — UUID identifying the worker task that claimed the job.
unique_key        — SHA-256 fingerprint when unique_for is set; NULL
                    otherwise.  Protected by a partial unique index.
errors            — chronological list of error messages from each attempt.
tags              — copy of JobConfig.tags at enqueue time.
typeDeadLetterDeadLetter = {#

DeadLetter mirrors the conduit_dead_letters DB schema. A row is written here when a job exhausts all retry attempts or is explicitly discarded with a dead-letter queue configured.

id                 — UUID of the dead-letter row (different from job_id).
job_id             — UUID of the originating job row.
queue / job_type / payload — copied from the originating JobRow.
errors             — full error list including the final failure message.
attempts           — total number of execution attempts made.
first_attempted_at — started_at of the very first attempt.
last_attempted_at  — time of the final failed attempt.
discarded_at       — time the dead-letter row was inserted.
reviewed           — set to true by a human operator after triage.
reviewed_by        — identifier of the operator who reviewed.
reviewed_at        — time of review.
retry_count        — number of times this dead-letter has been re-enqueued
                     via the dashboard "Retry" action.
typeNodeInfoNodeInfo = {#

NodeInfo mirrors the conduit_workers DB schema. Each process that calls Conduit.API.start registers a row here and refreshes it via heartbeat.

id           — stable node identifier (from Config.node_id).
hostname     — OS hostname of the node's machine.
pid          — OS process ID.
queues       — list of queues this node is polling.
pool_size    — workers_per_queue value (total pool = pool_size × |queues|).
started_at   — time Conduit.API.start was called on this node.
last_seen_at — updated every heartbeat_interval_ms; used to detect crashes.
status       — "running" | "stopped" | "stale".
typeWorkflowErrorWorkflowError =#

WorkflowError is returned by workflow runner functions to signal how execution ended.

Failed(msg)       — the workflow function returned an error; the job is
                    marked "failed" and not retried.
Cancelled(msg)    — the workflow was cancelled via `cancel_workflow`; the
                    job completes cleanly (no retry).
TimedOut          — `WorkflowConfig.timeout` elapsed; the row is marked
                    "timed_out".
StorageError(msg) — a checkpoint or storage call failed transiently; the
                    workflow job is retried via the normal backoff path.
typeExecutionModeExecutionMode = Checkpoint | DeterministicReplay#

ExecutionMode selects the checkpoint durability strategy:

Checkpoint          (default) — each `checkpoint` call writes directly to
                                `conduit_checkpoints`.  On resume, completed
                                checkpoints are loaded from the DB and their
                                functions are skipped.
DeterministicReplay           — each `checkpoint` call appends to the event
                                store (`conduit_workflow_events`).  On resume
                                the full event log is replayed in order,
                                making the execution deterministic.  Use this
                                when you need full audit history or
                                point-in-time replay.
typeWorkflowConfigWorkflowConfig = {#

WorkflowConfig is passed to Conduit.API.register_workflow.

execution_mode  — checkpoint durability strategy (see ExecutionMode).
timeout         — optional maximum wall-clock duration (ms) for the whole
                  workflow.  When elapsed the workflow runner marks the row
                  "timed_out" and stops retrying.  None = no timeout.
tags            — labels forwarded to the workflow runner job row.
typeWorkflowHandleWorkflowHandle = {#

WorkflowHandle is returned by Conduit.API.start_workflow. It carries the minimum information needed to poll status or send signals.

id             — UUID of the workflow row.
workflow_type  — the registered type name.
started_at     — time the row was inserted.

WorkflowRow mirrors the conduit_workflows DB schema.

id            — UUID primary key.
workflow_type — registered type name (key into the workflow registry).
parent_id     — UUID of the parent workflow, when this was spawned as a

error         — error message for "failed" / "cancelled" / "timed_out".

tags          — copy of WorkflowConfig.tags.

WorkflowSignal mirrors a row in conduit_workflow_signals.

id           — auto-increment integer primary key.
workflow_id  — foreign key to conduit_workflows.id.
signal_type  — string that the workflow is `wait_for_signal`-ing on.

typeWorkflowContextWorkflowContext = {#

WorkflowContext is threaded through every workflow function and passed to checkpoint, parallel, and wait_for_signal. Application code should treat it as opaque; create one via WorkflowContext.new (done automatically by the workflow runner).

workflow_id     — UUID of the running workflow.
parent_id       — UUID of the parent workflow (None for root).
namespace       — dot-separated prefix for checkpoint names within parallel
                  branches; empty for the root context.
checkpoint_key  — Vault table key used as the in-process checkpoint cache.
typeWorkflowEventWorkflowEvent = {#

WorkflowEvent mirrors a row in conduit_workflow_events. Events are append-only and form the source-of-truth for DeterministicReplay mode.

id          — auto-increment integer primary key.
workflow_id — foreign key to conduit_workflows.id.
sequence    — 0-based monotonically increasing index within the workflow.
event_type  — "checkpoint" (only type in Phase 3; more planned).
payload     — JSON: {"name":"…","value":…,"duration_ms":N}.

typeAuthAuth =#

Auth controls access to the web dashboard. Pass it when mounting the dashboard router.

None      — no authentication; the dashboard is publicly accessible.
            Only use on internal-only networks.
Token(t)  — require the HTTP `Authorization: Bearer <t>` header.
            Comparison is NOT constant-time in the current implementation;
            use `Fn` with `Crypto.secure_compare` for production.
Fn(f)     — call `f(authorization_header_value)` on each request.
            Return true to allow.  The full header value is passed,
            including the "Bearer " prefix if present.

interfaceStorageStorage(s)#
